# AB Test 与 Uplift：现有证据和下一轮实验

## 历史复盘

200,039 位客户按原数据的 treatment_flg 比较之后是否购买。主统计为两组均值差、未合并方差 Wald 95% CI、合并零假设方差的双侧 z-test；二元结局同时用组内 binomial bootstrap 核对区间。大样本近似适用；小样本子群不照搬 Wald。

SRM 使用预期 50/50 的假设诊断，官方分配比例未经独立审计。数值特征用标准化均值差，类别转成各水平比例；缺失率也检查。年龄子群 BH 校正，只用于生成假设，不依据探索性 p 值选上线人群。

现有数据没有分配日志，不能确认 treatment_flg 等于原始 assignment；因而不将两组差称为已审计的 ITT。也没有发送成本、结局收入、退订与投诉，不能计算历史真实 ROI。

## Uplift 评估协议

用户互斥的 60% train /20% validation /20% test，按 treatment×target 联合分层，seed 固定。缺失插补和类别编码仅在 train 拟合。完整历史商品明细先聚合成交易，再聚合成用户；不截取 purchases 前 N 行（其顺序并非随机样本）。

- Response baseline：只预测购买概率，说明“容易买”与“触达才多买”不同。
- Random baseline：与结果无关的固定随机排序，仅为一次可复现参考，非多次随机均值。
- S-learner：一个模型估计 P(Y|X,T)，相同 X 分别设 T=1/0 预测相减。
- T-learner：两个 treatment arm 模型，预测相减。比 S 灵活，但相减会放大估计噪声。

固定模型容量（120 rounds、15 leaves、leaf≥200、L2=10），避免在小用户分层中过拟合。候选 S/T 按 **validation Top30 uplift** 选择，之后冻结；test 的 Qini、AUUC、Top30 和十分位图只负责评估，不再选模型。保存分组与 holdout ID 在 gitignore 的 processed 目录便于复核。

Top30 bootstrap 区间条件于已训练模型/已选择用户，不包含训练不稳定性。基准间单独 CI 不能当作配对差值显著性检验；不以 test 曲线挑覆盖率。部署前需多 seed /交叉拟合稳健性和新的策略随机实验。

## 下一轮短信/优惠券分发实验（设计案例，未执行）

研究问题：相同预算下，uplift 策略是否比现有策略带来更多增量贡献利润？如果只验证短信有没有作用，用客户级“触达/不触达”随机对照；如果比较分发策略，用“现有策略/uplift 策略”随机对照，每组触达预算相同，保留独立无触达组用于估计自然转化（样本量需考虑多组比较）。

在符合营销资格的用户全集上用稳定用户 ID 随机分组；同一用户多设备一致，可按地区、历史价值分层。平台与门店存在互相影响时考虑门店/地域 cluster 或 switchback，不直接假设用户独立。

上线前记录：资格 SQL、分配表、分配比例、触达内容和频率、模型版本、预算、主结局窗口、MDE、alpha/power、停止规则。窗口需业务确认（如 14 天只是拟议值，不是 X5 已知结局窗）。

主指标为每位符合资格用户的贡献利润，包含商品毛利、券核销、触达成本与可能的履约成本；guardrails 为退订、投诉、取消、履约和用户体验。按原始分配 ITT 分析，不只看打开/领券/购买的人，避免干预后的选择偏差。先做 A/A 与 SRM、用户串组、事件完整性检查。实验开始后不每日看 p<.05 就停；固定样本/窗口或预先设计序贯方法。

二元购买率样本量函数使用双侧两比例正态近似；例如基线 60%、MDE 1pp、power80%、alpha5%。这是新实验规划，不用已观测 uplift 做“事后 power”。如果主结局是利润，应根据用户级利润方差、聚类和重尾重新计算，不能套二元样本量。

策略是否上线同时看区间、业务最低收益、guardrails 和成本；显著不等于有利可图，不显著不等于完全无效果。
