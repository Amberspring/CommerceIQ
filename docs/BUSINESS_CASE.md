# CommerceIQ：一次真实电商异动的完整分析工作流

主案例是巴西 Olist 电商交易，不是美团业务，也不是模拟内部实习。目标是回答：2018 年 6 月较 5 月的完成订单商品 GMV 为什么下降，哪些解释有证据，应该优先查什么？X5 作为同一项目的独立营销扩展，不关联两套用户或财务结果。

## 1. 业务问题和指标口径

经营人员看到销售下降，首先需要区分：购买规模减少、复购减弱、消费金额减少，还是数据和统计口径变化。不同解释对应不同工作：前者查获客与购买转化，中间查购买周期与体验，后者查价格和品类结构。

本项目 GMV＝最终状态 delivered 订单的商品 price 之和，按购买月归属，不含运费，不等于平台营收或利润。它是事后完成订单口径，不是当时可实时观测的成交指标。购买人数按 customer_unique_id 去重，订单量按 order_id，频次＝订单量／人数，AOV＝商品 GMV／订单量。

## 2. 先确认变化是否可信

9 张原始表的订单总量为约 10 万；16 项检查验证唯一键、关联覆盖、订单与商品粒度、支付及商品金额守恒。商品、支付、评价先分别降至订单粒度再关联，最新评价用于订单级描述。这些检查不等于能访问原业务的埋点、ETL 延迟或完整财务账本。

5 月 GMV 977,544.69 BRL，6 月 856,077.86 BRL，下降 121,466.83 BRL（12.43%）。不同口径下：

| 检查 | 真实结果 | 能判断什么 |
|---|---|---|
| 两月前 28 天 | -9.70% | 月份天数差不足以解释全部下降 |
| 未取消／不可用订单口径 | -13.05% | 更换最终状态范围后仍下降 |
| 相同星期结构的日均销售 | -7.72% | 将各星期几日均 GMV 等权平均后仍下降；不是对月度下降的因果分解 |

等长窗口、星期标准化均不能自动控制节假日、趋势、数据缺失或营销活动。案例是在历史趋势中选择的探索性复盘，不是假设检验后的因果事件。

## 3. 先拆公式，再选有业务理由的维度

GMV＝购买人数×购买频次×客单价。使用三因素六种替换顺序的 Shapley 平均分配交互项：

| 因素 | GMV 金额贡献／BRL | 相对上期 GMV 的贡献 |
|---|---:|---:|
| 购买人数 | -90,785.32 | -9.29pp |
| 购买频次 | -1,907.79 | -0.20pp |
| 客单价 | -28,773.72 | -2.94pp |

人数贡献约占净下降的 74.7%，所以优先看购买群体及其分布，而非直接把原因归给复购。

| 下钻维度 | 业务理由 | 字段能证明的范围 |
|---|---|---|
| 时间 | 判断何时开始、是否比较窗口造成 | 日／月、相同星期几；不冒充活动日志 |
| 地区 | 区分普遍下降和局部市场集中下降 | 用户州与城市；州不是完整供需市场 |
| 首次／已有购买群体 | 区分首次观测购买与历史购买用户的金额变化 | 首次完成购买所在月；不是注册时间、获客或流失 |
| 品类 | 区分商品需求、价格与结构变化的线索 | 商品分类与成交金额；无曝光与库存 |
| Seller | 区分既有活跃卖家掉量与交易覆盖变化 | 观察有单／无单；不是开业、停业或退出 |
| 履约与评价 | 检查服务体验是否伴随异常，规划后续复购分析 | 完成后的迟到、时长、评分；须考虑发生时间与观察范围 |

## 4. 用数据筛选解释，而不是罗列猜测

**购买群体：** 首次观测购买群体 GMV 减少 122,440.30 BRL（-12.53pp），已有购买群体增加 973.47 BRL（+0.10pp）。因此已有购买群体的金额下降没有驱动此次净下降。但不能据此说获客投入减少：没有流量、注册或广告字段。

**空间与品类：** SP 州减少 84,031.42 BRL，watches_gifts 减少 34,337.41 BRL。两者重叠，不相加。实际交叉拆解中，SP × watches_gifts × 首次观测购买群体减少 18,932.20 BRL（-1.94pp），为州×品类×群体切面中的最大下降项。说明这个切面优先级较高，但其贡献不能解释全部下降，也不证明“钟表礼品需求下降”的因果机制。

**Seller：** 两月持续有完成订单的 799 位 Seller 减少 120,489.82 BRL；6 月无单的 306 位 Seller 减少 115,386.80 BRL；新增或恢复交易的 366 位 Seller 增加 114,409.79 BRL，后二者净减少仅 977.01 BRL。单看无单 Seller 会夸大其净解释。应优先检查持续活跃 Seller 的商品、购买群体和价格结构，而非立刻建议加大卖家招商。

**履约：** 完成订单迟到率由 6.56% 降至 1.16%，平均送达天数由 11.34 降至 9.16，平均评分由 4.24 升至 4.31。取消／不可用订单占比由 0.58% 降至 0.36%。这些汇总不支持“同期履约普遍恶化”的描述，但不排除局部问题、前期体验或最终完成状态的选择偏差；履约与评价发生于购买之后，不将其当成当月购买量的原因。

## 5. 结论、行动顺序与验证标准

可确认的是：下降在多种口径下仍存在，购买人数是最大算术贡献项；首次观测购买群体和持续活跃 Seller 是优先排查对象，SP × watches_gifts 的首次购买切面值得重点关注。尚未确认曝光、价格活动、库存或竞争的机制。

| 优先级 | 下一步行动 | 验证标准／需要的数据 |
|---|---|---|
| P0 | 业务方核对时间范围与数据到达情况 | 订单日覆盖、源系统抽取日志、同口径财务记录；避免把导出缺口当下降 |
| P1 | 排查持续活跃掉量 Seller 与重点交叉切面 | 曝光→点击→下单转化、在售 SKU／可售库存、价格与活动记录；区分流量少、转化差和商品不可售 |
| P2 | 根据 P1 结果确定动作 | 曝光问题检查分配与获客；转化问题检查商品价格和页面；不可售检查备货与上架。不是未经验证就发券 |
| P3 | 建立监控并验证动作 | 同星期几日级 GMV、首次购买人数、AOV、卖家与品类覆盖、取消与迟到；记录动作时间、对照组与成本 |

监控使用已有过去八周同星期几中位数／MAD 异常提示，阈值为排查入口，不能宣称具备线上预警 SLA。真实验证动作效果需随机实验，或在可辩护假设下设计准实验；本项目没有执行企业动作。

## 6. AI 实际用于哪些工作

本轮 Codex 编码助手实际辅助了 SQL 编写、业务假设整理、结果解读及本报告草稿。提示词、候选查询和假设保存在 `docs/ai_review_input.json`；运行 `scripts/run_diagnostics.py` 可重做 SQL 结果审核与数据取证。该脚本是确定性验证，不执行模型推理，也没有虚构 LLM API 接入。

审核案例主动生成一个商品×支付×评价直接关联的反例：它将 5 月 GMV 算成 1,013,168.64 BRL、6 月算成 900,971.61 BRL，无法通过金额契约；复用订单粒度模型后分别为 977,544.69 与 856,077.86 BRL，通过校验。这是明确标记的压力测试，不是声称 AI 曾在生产环境犯错。

AI 提出的解释也经过证据分级：H1“天数／星期结构解释全部下降”不足以成立；H2“首次观测购买是主要下降群体”有金额桥接支持；H3“优先查交叉切面”有定位支持；H4“无单 Seller 解释全部下降”遗漏新增抵消；H5“同期履约变差”不受汇总指标支持且有时序问题；H6“曝光、缺货或活动导致下降”缺字段，保留为取证方向。

AI 提供候选，SQL／Python 计算证据，审核控制结论边界。候选与审核由同一助手完成，并非独立人工评审；用户应复现、理解并抽查后再在面试中使用。没有评估 AI 生成成功率，也没有测量节省工时，不写相关收益数字。

## 7. 手动复现与讲解顺序

在项目目录的 PowerShell 中运行：

```powershell
.venv/Scripts/python scripts/run_olist.py
.venv/Scripts/python scripts/run_diagnostics.py
.venv/Scripts/python scripts/render_report.py
.venv/Scripts/python -m pytest -q
.venv/Scripts/python scripts/check_dashboard.py
.venv/Scripts/python -m streamlit run dashboard/app.py --server.address 127.0.0.1
```

口头讲解按“问题—口径与数据检查—公式拆解—业务维度—假设验证—建议与待取证数据”展开。90 秒主讲 Olist；被问 AI 时打开候选与审核；被问 AB／营销时再讲同项目的独立 X5 扩展。
