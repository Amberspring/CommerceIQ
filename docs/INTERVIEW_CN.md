# CommerceIQ 面试讲解与追问

用途：把真实完成的工作讲清楚。数字以 `FINDINGS.md` 与 outputs 为准。不要称作企业实习、线上项目或已落地提升；不要背诵自己无法解释的术语。

## 60 秒版本

主讲版本以 [BUSINESS_CASE.md](BUSINESS_CASE.md) 为准；简历只展示一个 CommerceIQ，X5 是独立数据扩展，追问营销时再讲。

“我做了一个基于 Olist 真实电商数据的经营异动诊断项目。先用 SQL、Python 和 DuckDB 建订单分析层，通过16项检查避免多表关联造成重复计数，再复盘2018年5到6月商品GMV下降12.43%的案例。

我先按购买人数、频次和客单价拆公式，人数变化占净下降约74.7%，所以继续查购买群体和地区、品类、Seller的交叉切面。结果集中在首次观测购买群体和持续活跃Seller；相同天数和星期结构下仍下降，同期汇总履约指标反而改善。因此我明确优先查哪些群体、需要哪些曝光和库存证据，没有直接认定缺货或流量减少。

我也用Codex辅助SQL和假设整理，保留提示词与审核记录，通过金额契约检查重复计数，并用交互看板展示结果。项目串起了从业务问题到数据处理、假设验证和建议输出的流程。”

### 原扩展版：被问 AB／Uplift 时补充

“我做了一个基于公开真实数据的电商经营分析项目。主线是 Olist 的订单、商品、用户、Seller、支付和评价数据，先统一指标口径并处理多表 JOIN 重复，再建立 GMV 指标树、用户分层和卖家留存。

我复盘了 2018 年 5 到 6 月完成订单商品 GMV 下降 12.43% 的情况。用 Shapley 将变化精确分给购买人数、频次和客单价，发现人数变化贡献最大，再按州、品类和 Seller 下钻。两月前 28 天和未取消订单口径仍然下降，但我把算术贡献与真正的因果根因分开，缺少流量和库存数据的部分列为待验证假设。

Olist 没有实验字段，所以我用独立的 X5 RetailHero 做短信触达评估，用全量历史交易构建特征，训练 S/T uplift 模型，验证集选模、独立测试集评估，最后做了交互 Dashboard。这个项目让我把指标定义、SQL、经营诊断与实验思路串起来。”

## 5 分钟版本：按问题—方法—证据—限制讲

### 1. 为什么选这个问题（30秒）

我希望能够回答“GMV 为什么下降、哪些供需群体变化、应该优先查什么”，而不只做销售图表。Olist 是真实关系型电商数据，适合交易经营问题；RetailHero 提供独立的触达/购买标签，避免在 Olist 人造 A/B 分组。

### 2. 怎样保证数字可信（60秒）

GMV 定义为最终完成订单的商品金额，按下单月归属，不包含运费、不称作平台营收。明细表、支付表、评价表直接 JOIN 会乘出重复行，所以我先分别聚合至 order_id；评价按最新观测记录去重。16 个质量检查覆盖唯一键、FK、粒度和金额守恒。购买人数使用 customer_unique_id，不使用每单变化的 customer_id。

例子：一单 2 个商品、2 个支付记录、2 条评价，直接 JOIN 可产生 8 行，商品价格重复 4 次。这不是“业务增长”，是建模错误。

### 3. 如何拆解 GMV 异动（90秒）

2018-05/06 完成商品 GMV 为 977,544.69/856,077.86 BRL，下降 12.43%。先用 Buyers×Frequency×AOV 恒等式，不把曝光转化漏斗塞进没有曝光数据的表。

三个因素同时变化存在交互项。我把三因素的六种替换顺序取平均，人数贡献约 −90,785 BRL、频次 −1,908、客单价 −28,774，严格加总为 −121,467。人数变化解释最多，再看 SP 州贡献 −8.60pp，watches_gifts 品类 −3.51pp。它们是同一批订单的不同切面，不能相加。

按两月前28天比较仍降9.70%，未取消口径降13.05%；等权星期结构日均GMV仍降7.72%。已完成交叉下钻：SP×watches_gifts×首次观测购买群体减少18,932.20 BRL。持续活跃Seller减少120,489.82 BRL，新增／恢复和当月无单Seller几乎抵消；同期迟到率和平均评分改善。下一步应针对上述切面索取曝光、可售库存和活动记录，不能只凭交易表证明机制。

### 4. 用户和 Seller 怎样产生业务价值（50秒）

Olist 主窗口只有约 3% 的购买用户复购，频次分位数很容易出现大面积并列。我采用透明规则，把近期/不活跃与一次/多次购买组合成四层，不包装成预测 CLV。Cohort 用首次观测完成购买，未来月份留空。

Seller 先按 seller-order 聚合服务指标，以免一个订单多商品放大权重。用月活 Seller 次月仍有完成订单衡量活动留存，最后观测月不算流失；用新增/恢复、持续、当月无单三类桥接 GMV。首单不是入驻，当月无单不是永久退出，小样本卖家先设最少订单数再看评价。

### 5. 实验与 uplift 做到哪一步（50秒）

RetailHero 有 200,039 位带标签客户和 4,578 万历史商品明细。purchase_sum 重复在商品行，我先按 transaction_id 聚合，再构建用户的消费额、频次、近30天频次、距上次交易天数和商品/门店多样性。

整体触达/未触达购买率差 3.32pp。全量历史特征下，按用户分 train60/validation20/test20；只在 train 拟合预处理。S-learner 在 validation Top30 指标获选，test Top30 的购买率差为 6.24pp，bootstrap 区间约 [4.31,8.02]pp。公开材料没有可独立审计的随机化日志，这些因果解释依赖分配假设；历史评估也不能替代新策略上线实验。

## 高频追问：先回答原则，再落到项目

**你到底找到“根因”了吗？**

找到贡献最大的指标和集中子群，尚未证实因果根因。人数是算术因子，州/品类是定位维度；供给、流量、需求变化是需要更多数据验证的机制。交易结果可以定位问题，不能自动区分“没曝光”与“曝光后不下单”。

**为什么不直接用订单量×客单价？**

可以，适合一级快速拆解。进一步拆成购买人数×频次，能区分购买用户规模与人均下单变化。指标树有重叠，不能把订单贡献和人数/频次贡献重复相加。

**为什么用 Shapley，有什么局限？**

在多个因素同时变化时，公平分配交互项并避免顺序任意性；本质仍是恒等式分配，因子高度相关，贡献不能解释为因果。三个因素简单枚举六种顺序，更多因素需考虑计算成本。改变指标树也会改变解释。

**如果某 Seller 突然掉单，你会怎么排？**

先核对数据到达、状态、商品/订单粒度和日覆盖，再看是否全品类/全区域掉、是否只高价产品掉、活跃买家还是频次变。对照相似 Seller 与相同星期几，检查迟到/评分是否在掉单前恶化。再索取曝光、点击、库存、价格活动、商品上下架与 Seller 停业记录，按时间顺序验证。不能只因评分同期降低就断言其导致订单下降。

**新开一批店但整体 GMV 没涨，怎么分析？**

先分新店、原有店、重新活跃店的贡献，再看新用户有没有增加、旧用户频次是否提升、客单价是否下降以及同区域老店被分流。Olist 只能用“首次观测有单 Seller”做描述代理，没有真实开业、位置曝光与供给量，无法严谨判断新店爬坡和蚕食。真实业务需拿开业时间、商圈流量、服务半径与原有店对照；若要因果识别，考虑随机扩展、分阶段上线或满足假设的差分法。

**怎么判断经营差还是平台流量给少了？**

需要分曝光×点击率×下单转化×履约完成率并对照库存、价格、营业状态。曝光少与转化差的改善动作不同；Olist 缺少前半段，不能给平台流量分配下结论。

**RFM 为什么不用五等分打分？**

频次大多数为 1，五等分会有并列、分箱失败或靠排序人为拆开相同用户。采用可解释的频次≥2、recency≤90天规则更诚实；阈值是业务启发式，需要未来实验验证，不是最优策略。

**留存低说明用户不喜欢平台吗？**

不能。品类耐用品购买周期、样本窗口、匿名化导出覆盖都会影响可观测复购。这里是购买 cohort 留存，不是 DAU/注册留存，也不是企业整体忠诚度。

**AB 显著是不是可以上线？**

先验证分配与数据质量，再看效应区间、实际业务最低收益、利润和 guardrails。显著的 0.1pp 可能亏钱；不显著不代表不存在实际效应。X5 没有利润与退订字段，现有结果不能完成上线决策。

**SRM 不显著就证明随机实验了吗？**

不能。数量接近 50/50 不排除按某种用户特征分配；协变量平衡也不排除未观测混杂。需要分配机制与执行日志。本项目对此保留条件性解释。

**样本量怎么算？**

上线前给定基线、最小值得检测的绝对提升、alpha、power、分配比例。二元结局两比例公式，MDE减半大致需要四倍样本。重尾利润、cluster 实验应按方差与设计效应另算；不拿事后显著结果反推“事后 power”当证据。

**购买概率高为什么不一定值得发券？**

有些用户不发也会买，响应模型会把他们排前面；uplift 估计发与不发的购买概率差。在同一预算下，应该优先考虑差值足够大、增量毛利超过成本的群体，不只看预测购买率。

**S 和 T learner 各有什么风险？**

S 用一个模型，样本共享、相对稳定，但模型可能忽略弱 treatment 信号；T 分别建模，更灵活，但两个估计相减可能增大方差，稀疏人群会不稳定。当前验证集选 S，不能推广成“S永远更好”。

**Top30 是不是作弊选出来的？**

覆盖率参照 RetailHero 官方竞赛的 Top30 评估规则预先固定。S/T 只由 validation Top30 选择；不看 test 来选覆盖率和模型。结果仍有训练变化的不确定性，后续应多 seed 验证，最终需策略随机实验。

**6.24pp 比整体3.32pp高，是否证明收益翻倍？**

不能。覆盖人数、触达成本、自然转化、结局收入不同；购买率差不是利润。单独两个估计的区间也不是二者差值的显著性检验。要同预算比较策略，按符合资格用户的平均增量贡献利润评估。

## 演示顺序与学习路径

1. README 的真实结论与数据来源，说明两个数据集分工。
2. Dashboard GMV 归因：指标树 → 州 → 品类 → 口径敏感性，指出维度不能相加。
3. 打开 `sql/01_order_mart.sql`，解释 child 预聚合、用户键和评价去重。
4. 用户页解释低复购与右删失；Seller 页解释首单/入驻和小样本。
5. AB 页解释率差/区间/随机化限制；Uplift 页解释 response/S/T、validation/test 和假设利润。

真正准备面试：先手算 Shapley 的两因素例子，再独立写 Seller 次月留存 SQL，之后复述实验设计与泄漏检查。至少能解释每个结果从哪个原始字段计算出来。
